决定

决定谁理由
后续裁判验收由设计负责人代行用户用户不是设计领域的，希望发挥设计负责人的领域能力
后两套体系只做网页，衍生产物和衍生脚本先不做用户三种载体加 PDF 每套都做一遍太繁琐，需要时再做
体系实现派给 Codex，设计负责人只定方向、写规则、评审用户（选项 B）token 应该主要花在 Codex 上；Claude 分身多次撞额度上限
精密工业取方向 B（铝板数据表），借用方向 A 的表盘作唯一的暗页高光设计负责人材质最直接，最不像应用界面，能延续「图解即文献」
孔版印刷取方向 A（双色海报），借用方向 C 的网格做数据类单元；只用两只墨设计负责人错版最有辨识度，也最容易设预算，正好验证 ADR-0001
验收中发现的首屏问题（字体晚到、元素提前显露、录屏太早滚动、字体太大）都先修再交验收设计负责人验收包要能当场看出动效和手感，这几处直接决定第一眼
字体子集提前到第 0 阶段做设计负责人#48 之后，字体加载时长直接决定首屏空白多久
幻灯片朱笔「一册不超过两页，且不相邻」；横排多字的大标题收紧字距设计负责人评审时发现连着三页朱笔会冲淡高光；收紧字距与工艺规范工-2 一致

问题与处理

问题处理
设计负责人的失误：体系实现交给了 Claude 子代理，没有派给 Codex。这偏离了双角色流程「把 token 花在 Codex 上」的初衷，结果四次撞上额度上限、两次卡住被中断。你指出后改为 B：体系实现派给 Codex。半成品留档在 design/ind、design/riso 两个分支，作为 Codex 的起点。
设计负责人的失误：自己做的体系有几处违反了自己写的规则，由第一批审查发现，包括朱笔早了 210 ms、列表没有错峰、字重、字距。当轮就改了；其中两条属于有意的例外，改写进了规则的适用边界。
#42 和 #43 分开验收都没问题，合在一起后，打印 PDF 时揭去层仍然可见。rebase 时测试失败，暴露了问题；退回 #42 返工，补了交叉测试。
#48（等字体就绪再入场）带出了「等待期间元素先露出来」，第二批审查又发现子元素还能露出。先后开 #51、#52 修复。这几个问题都是看录屏抽帧发现的，自动测试覆盖不到。
两套新体系第一版都偏「模板」：精密工业三段同构、光路图不对；孔版印刷识别符号缺失、中段太素。各退回五条，第二轮都改到位了。
验收评论脚本有一次 gh api 调用失败。原样重跑后成功，没有重复评论。

流程发现

  • 录屏抽帧是动效验收最有效的证据：本期 5 张工具单是看录屏拼图时发现的问题。建议验收产物默认带一张「前 N 秒抽帧拼图」。
  • 体系的审美工作量主要在排法和样张，渲染本身很便宜。把它们派给 Codex、设计负责人写清方向和评审意见，效果可以接受：两套体系都是两轮通过。
  • 分开的工程工单合在一起才暴露的问题出了两次（#42 + #43，#48 + #51）。对策是合并后在验收包层面再看一遍录屏。
  • 按批审查继续有用：三次共发现 12 条，其中 4 条是设计负责人自己的违例。

回报 video-studio

  • 设计工单派给子代理会撞上 Claude 额度上限、卡住。run-spec 可以写明：role:design 的大块实现，优先写成带方向裁定的工程工单。
