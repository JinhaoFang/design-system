问题与处理

问题处理
spec 写的"CI 机器 4 核"不对，实际是 2 核。这是设计负责人写 spec 时没有核实的前提，#33 按 4 核在本机复现不出来。#33 按工单允许的退路改在 CI 上诊断，才查清；本汇报更正。以后 spec 里写机器条件，先在 CI 上打印一次核实。
截图报错和"体系总览页有 4 个错误"的根因没有锁定，诊断时也没再出现。做了有依据的缓解；CI 失败时会自动保存检查报告，下次出现能看到是哪条规则。
#35 工单里写的恢复命令有副作用（设计负责人写的工单）。验收前实测发现，改写后再实测一遍；偏离写进了验收评论。
三张并行工单都往同几处登记处各加一项，后合并的两张出现冲突（6 个文件）。预料之中，是这次要演练的内容。按"类型检查 → 注释 → 文档命令 → 测试"的顺序合并，并统一改写了三份规则文档里的 verify 和 CI 描述。
文档命令检查对 node 路径只看进没进 git，不看文件是否实际存在。起因是设计负责人派发 #38 时写了"按进 git 的文件判断，不按本机磁盘判断"，本意是让本机和 CI 的结果一致，却漏了"还要存在"这一半。收尾审查发现后开返工单 #39，补上存在性判断，命令手册同步更新。
land 在 rebase 后不重新装依赖。#37 新增的依赖没有进 #38 的 worktree，验证一定会失败。手动在 worktree 里重装后重跑 land；本仓库执行配置说明里加了这一条。

流程发现

  • 标准派发指令和"要 CI 链接"的验收标准矛盾：指令写"不要推送"，但 CI 只在推送时运行。这次靠补充说明放开。建议 run-spec 支持在工单里声明"允许推送工单分支"，cleanup 顺带删掉远端的工单分支。
  • land 不重装依赖：应该在 rebase 改动了 lockfile 时自动执行安装命令。
  • 并行工单的共享登记处冲突：三张都要加 verify 步骤的工单，每合并一张，后面的都要手工解决冲突。对策：拆单时把"往登记处加一项"留给最后合并的一张，或者把登记处改成每项一个文件。
  • 按批审查和收尾审查重叠：最后一批审完紧接着就是整分支审查，可以合成一次。
  • 派发数据自动进验收评论，写汇报时很好用；按批审查的数据不进任何评论，要去 ~/.codex/sessions/ 里翻，审查内部开的子代理还要自己加总。

回报 video-studio

迁移和移植中发现的问题，供 video-studio 写迁移初始化技能时参考。

  • pnpm 12 的自带命令表：pnpm 12 改成原生发布包，没有 pnpm.cjs，help --all 不能用。整理方法：下载同版的包装包和平台包，核对 SHA-512，从 --help 收集命令和别名，再对照同版源码补隐藏命令和 pm 前缀。相对 10.34.6 新增 21 个名字（change、clean、dist-tags、lane、licences、owners、pack-app、peers、pipeline、pm、purge、rt、runtime、sbom、shim、ss、stage、stop、tasks、undeprecate、with），删掉 1 个（server）。另外 pnpm 12 不认 pnpm -s。
  • 仓库特有的 ds 子命令：子命令表抽成纯 JSON，命令行工具和检查器读同一份，检查时不导入、也不执行命令行工具。迁移初始化时要问清目标仓库有没有类似的"脚本下的子命令"。
  • node <路径> 按 git 跟踪清单判断：被忽略的路径要从祖先目录判断，否则 worktree 里的软链接会让 git check-ignore 报 path beyond symbolic link。
  • 占位符：不能因为参数里有占位符就跳过整条命令，否则 pnpm ds missing --system <dir> 这类错误会漏掉。
  • 提交信息规则：范围从"小写字母、数字、连字符"放宽为"非空、内容不限"；入口统一用共享命令行辅助；不移植纯函数的测试，只保留覆盖规则边界的入口测试。
  • 注释检查：本仓库收紧了 video-studio 的做法：只认第一段文件头，指令注释不设例外，只查进 git 的文件。TypeScript 7 没有解析接口，要另装 TypeScript 6 的别名。
  • CI 机器核数：GitHub 的 ubuntu-24.04 runner 实测 2 核（私有仓库）。测试并发数要按实际核数取，不能写死。
  • run-spec 本身：上面"流程发现"里的推送、重装依赖、审查重叠三条。
