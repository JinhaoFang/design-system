# 面向 AI Agent 的设计体系库：方案 v0.3

草案 v0.3 · 2026-10-10 · 以 v0.2 为基线重写，逐轮讨论后确认。术语以 [`GLOSSARY.md`](../GLOSSARY.md) 为准，关键取舍见 [`docs/adr/`](adr/)。

## 1. 美学立场

> 天有时，地有气，材有美，工有巧，合此四者，然后可以为良。
> ——《考工记》

哪些体系可以入库、检查器查什么、成品怎样才算好，都从这份立场推出。

1. **天时：为何而做。** 先弄清场合与目的。每个设计决定都要说得出为内容和观看者做了什么，说不出理由的就删掉。
2. **地气：在哪被看。** 设计服从观看者与载体。落地页要在几秒内讲清楚，幻灯片要在远处看得清，社交配图要先在信息流里被看见。同一套语言换了载体，就要换一种说法。
3. **材美：忠于材质。** 每套体系属于一种具体的材质，光、色温、表面、边缘和动效手感都由材质推出，动静同源。只取材质的意象，不照搬它的外观。
4. **工巧：经得起近看。** 质感来自工艺，而不是特效：对齐、字距、灰阶、比例和细节精度。
5. **克制。** 强调色、装饰和动效都有预算。一屏只有一个主角，力气花在一两处值得记住的地方。
6. **耐看。** 第一眼不必惊艳，第十眼仍然舒服。这是「良」的检验标准。

《考工记》接着说：「材美工巧，然而不良，则不时，不得地气也。」材料好、工艺巧，结果仍可能不好，原因是场合和观看者不对。照搬一套好看的体系常常形似神不似，原因就在这里。所以迁移一套体系时，必须连同它的意图一起判断。

立场是品质门槛，不是风格过滤（[ADR-0001](adr/0001-quality-bar-not-style-filter.md)）。极繁、国潮红金这类热闹的风格同样可以入库；「花里胡哨」是执行失败，由第 4、5 条淘汰。

## 2. 定位与差异

### 2.1 定位

一句话：让说不清需求的人，也能拿到克制、有质感、动起来也讲究的网页、幻灯片和配图。

- **第一承诺：听懂模糊的话。** 需求方说「高级一点」「再活泼些」，agent 能把它变成看得见的设计决定。
- 体系库是兑现这个承诺的手段，提取是体系库的来源之一。
- **非目标**：UI 组件库、应用界面、Figma 导入导出、通用设计工具、以数量取胜的风格目录。

本库所说的「设计体系」，指一套可迁移的设计语言，接近一份艺术指导方案，而不是某家公司为自家产品维护的 design system。

### 2.2 需求方、裁判与 agent

| 角色 | 是谁 | 要什么 |
| --- | --- | --- |
| 需求方 | 项目发起人和少数同事，多数不是设计师 | 说清楚要做什么，快速拿到有质感的成品；说不出设计术语，看得出不好看却说不出哪里不好 |
| 裁判 | 项目发起人 | 对成品好坏做最终判断，每次挑选都沉淀进品味笔记 |
| agent | Claude Code、Codex | 清晰的简报、可执行的规则、能自查的工具；默认审美趋于平均，看不到自己产出的实际画面 |

流程按「一位裁判、少数需求方」设计，力求轻量，不做多人评审，也不统计评审一致率。

### 2.3 现有项目格局

| 类型 | 代表 | 强项 | 对本库的意义 |
| --- | --- | --- | --- |
| 规范格式与合集 | DESIGN.md、awesome-design-md | token 格式、品牌合集 | 作为导出格式 |
| 风格数据库 | ui-ux-pro-max | 大规模的风格、配色、字体目录与行业规则 | 不在数量上竞争，借鉴其反模式 |
| 设计方法 skill | oil-ui、taste-skill | 定调、拉开方向、反 AI 味、做减法 | 借鉴方法 |
| 载体引擎 | ppt-master | 原生可编辑的 PPTX 与原生动画 | PPTX 导出的候选后端 |
| 提取器 | iFurySt/DESIGN.md、arvindrk/extract-design-system 等 | 从网页或图片提取 token | 多数产出文件就结束，缺少验证 |
| 整合平台 | Open Design | 154 套体系、模板，以及通用工艺规则（`craft/`） | 体系里已写明理由与反模式；但每套体系的动效只有几条悬停与过渡规则 |

「规则写明理由」和「通用工艺规则」已经有人在做，单靠机制拉不开差距。本库的差异落在四点：

1. **质感 = 材 + 工。** 每套体系都从一个材质锚点出发，静态质感和动效手感同出一源。工艺规范全库通用，并尽量写成脚本。
2. **动效是一等公民。** 每套体系都有完整的动效语言，动效性格由材质推出，并能映射到各个载体。现有项目要么把动效当成一个强度开关，要么只有通用纪律，没有属于某套体系的动效性格。
3. **听懂模糊的话。** 感觉词词典把有歧义的模糊词拆成几种解读，再用大白话复述给需求方挑选，不让 agent 悄悄选走最平庸的那一种。
4. **不撞模板。** 结构骨架只是叙事单元的词汇表；体系为每个单元提供多种排法，并规定整页节奏；每件作品都必须有自己的作品概念。

支撑这四点的是品味笔记和精选的范例库。库用得越多，就越贴近裁判的品味。

## 3. 体系模型

### 3.1 质感：材与工

**材（材质感）。** 每套体系的开头是一句材质锚点，例如「暖白手工纸上的油墨印刷」「阳极氧化铝与冷色背光」。以下各项都由它推出：

| 方面 | 推出什么 |
| --- | --- |
| 光 | 光源方向和软硬，阴影的层数与色温；阴影带环境色，不用纯黑半透明 |
| 表面 | 哑光还是光泽，颗粒与噪点的强度上限 |
| 边缘 | 发丝线、毛边、机加工直角，或柔和圆角 |
| 色温 | 中性色偏冷还是偏暖；不用纯黑纯白 |
| 图像处理 | 调色和颗粒与材质一致 |
| 手感 | 动效的重量、摩擦、阻尼与回弹：纸滑一下再停，陶瓷落得沉，铝停得准 |

护栏：**隐喻，不模仿。** 材质靠光、色温、颗粒、边缘和运动方式来体现，不贴写实的木纹、皮革贴图，除非体系的意图明确需要。

**工（工艺感）。** 指与风格无关的细节精度，写成全库通用的工艺规范，各体系只调参数。例如：

- 按视觉效果对齐，而不是按坐标对齐
- 大标题收紧字距，小字放开字距
- 中文标点挤压，中西文之间留间距
- 圆角嵌套：外圆角 = 内圆角 + 内边距
- 图标线宽与正文字重匹配
- 数字用等宽字形

能机械判断的项都放进检查器。

### 3.2 一套体系的六个部分

| 部分 | 回答什么 | 包含什么 |
| --- | --- | --- |
| 意图（天时、地气） | 为谁、为什么 | 适用场景与观看者、传达目标、调性位置、关键规则的理由与适用边界 |
| 材质锚点（材） | 属于什么材质 | 一句话的锚点，以及由它推出的光、表面、边缘、色温和手感 |
| 视觉语言 | 长什么样 | 色彩；字体（含中文搭配与中西文混排）；版面（含构图比率、整页节奏、各叙事单元的排法）；形态；图像与画风（含素材来源与无图方案）；识别符号 |
| 动效语言 | 怎么动 | 动效性格（来自手感）、时长与缓动阶梯、编排规则、高光时刻、在各载体上的对应做法 |
| 结构骨架 | 用哪些叙事单元 | 以全库各载体的骨架为基础，可以增加本体系专属的单元 |
| 范例 | 拿什么证明 | 标准样张在各载体上的渲染结果，以及来源作品（如果有） |

每套体系必须具备以下几项：材质锚点、动效语言、中文字体搭配、1–3 个识别符号、无图方案。

关键规则一律分三段写：**规则、理由、适用边界**。例如：

- 全页只有一处用强调色 / 让行动按钮成为唯一主角 / 任何载体都成立。
- 正文每行不超过一定字数 / 保证手机上的阅读体验 / 迁移到幻灯片时不成立，改用幻灯片的字号下限。

迁移时逐条检查理由在新场景下是否还成立。迁移因此变成「判断哪些取舍仍然有效」，而不是照搬数值。

### 3.3 调性刻度

刻度是感觉词与设计决定之间的中间坐标，也用于检索时排序。需求方从不直接调刻度。每组分五档：

| 刻度 | 控制的设计决定 |
| --- | --- |
| 静—动 | 色彩饱和度、跳跃率、动效的幅度与频率 |
| 疏—密 | 版面率、图版率、间距阶梯 |
| 冷—暖 | 中性色的色温、材质的温度 |
| 轻—重 | 字重、明度对比、材质的分量、动效阻尼 |
| 庄—谐 | 对齐的严格程度、字体性格、是否允许俏皮的手法 |

冷暖和轻重的默认位置由材质锚点决定。

### 3.4 构图比率

构图用三个可测量的比率来表达：

- **跳跃率**：最大字号与正文字号之比
- **版面率**：内容区占画面的比例
- **图版率**：图片面积占画面的比例

每套体系声明三者的取值范围，检查器负责测量。感觉词的解读也用它们来落地，例如「大气」的一种常见解读，大致就是高跳跃率加低版面率。

### 3.5 动效语言

- **目的**：每条动效规则都标明属于哪一类：反馈（我点到了）、导向（从哪来、到哪去）、层级（先看哪里）、叙事与情绪（记住这一刻）。说不出目的的动效不进体系。
- **预算**：每件作品只有一两处高光时刻，其余地方保持安静。
- **底线**：默认只动 transform 和 opacity；尊重系统的「减少动态效果」设置。
- **跨载体**：同一套动效语言在不同载体上，时长和缓动的比例关系保持一致，具体形式按载体能力映射。

| 载体 | 动效形式 |
| --- | --- |
| 展示型网页 | 交互反馈、入场编排、滚动叙事 |
| HTML 幻灯片 | 翻页、元素出场、关键页的高光时刻 |
| 社交配图 | 没有动效，用构图暗示运动（斜线、方向感） |
| PPTX 导出（第 3 阶段） | 映射到 PowerPoint 原生的转场与对象动画 |

跨载体时存比例关系，不存绝对数值：字号存字阶比例，时长、间距、圆角存为基准值的倍数，每个载体各配一个基准值。

### 3.6 结构骨架与防同质化

同质化有三个来源：叙事顺序固定（首屏 → 问题 → 方案 → 特性 → 证据 → 行动号召）、槽位固定（「特性」永远是三张等大卡片）、每个单元只有一种排法。对策如下：

- **骨架是词汇表，不是模板。** 每件作品用哪些叙事单元、按什么顺序、哪些合并，由这次的内容决定。比如一个摄影展的落地页，可能只有「首屏、一面展墙、地址」三段。
- **叙事单元只规定内容**：有哪些槽位、主次如何、字数上限多少，不涉及任何几何信息。
- **几何归体系管。** 每个叙事单元有 2–4 种排法；整页节奏另有规则，例如纸本编辑体系是「两三段安静的阅读之后来一次满版高潮」，且相邻单元不能用同一种排法。
- **每件作品有一个作品概念**：从这次内容中提炼出的一句话视觉点子，例如「像一本技术手册的扉页」。它落在一两处专门设计、不套用排法的地方，通常是开场和高光时刻。
- **换肤**：同一份内容换上另一套体系的排法和样式。**换骨架**：同一套体系换到另一个载体，改用该载体的叙事单元。

第一期的叙事单元（可选清单，不规定顺序）：

| 载体 | 叙事单元 |
| --- | --- |
| 展示型网页 | 首屏、问题、方案、特性、证据（数据、引用、客户标识）、流程、行动号召、页脚 |
| HTML 幻灯片（16:9） | 封面、目录、章节、观点（一页一个主张）、数据、对比、流程或时间线、引用、图片、结尾 |
| 社交配图 | 标题型、金句型、清单型、数据型；画幅为公众号封面 2.35:1、小红书 3:4、方形 1:1 |

### 3.7 全库共享资产

- **美学立场**：见本文第 1 节。
- **工艺规范**：见 3.1。
- **字体清单**：每款字体都标注授权状态、可用于哪些载体，以及是否属于 PPT 安全字体（常见系统自带的字体）。可免费商用的中文字体很少，必须逐款核对官方授权。网页上的中文字体要子集化。
- **感觉词词典**：见第 4 节。
- **反模式清单**：从 ui-ux-pro-max 和 taste-skill 的反模式条目起步，加上我们观察到的问题（比如所有内容都居中、等大卡片网格），之后持续补充。
- **范例库**：见 3.8。
- **标准样张**：见 3.9。
- **品味笔记**：见 5.3。

### 3.8 范例库

- **标准**：精选，宁缺毋滥，不设数量目标。入库必须经裁判批准。
- **来源**：
  - 外部收集：设计奖项与精选网站、品牌官网、优秀的发布会幻灯片等。
  - 自创：包括临摹（为了学习亲手重做外部范例）和原创（用本库体系做出的页面、生成的图片等）。
- **每条范例包含**：截图（有动效的附录屏）、来源，以及标注。标注写明出色在哪、为什么出色、适合什么场景、对应什么材质锚点和调性位置。
- **用途**：校准 agent 的审美；给感觉词的各种解读提供样图；作为裁判判断时的对照。
- **边界**：外部作品只用于参考和判断，不用进交付物。截图只存在私有仓库里；仓库公开之前移除截图，只保留链接和标注。
- 材质本身的参考照片（比如一块釉面陶瓷的特写）不算范例，可以用生图或图库。

### 3.9 标准样张

标准样张是一份固定的测试内容，每套体系都用它渲染一遍。内容不变，比较时看到的差异就只来自体系本身。

- **内容**：一座虚构的山顶天文台，新望远镜落成，开放公众观测夜。内容刻意覆盖全部叙事单元，数据、引用、流程、图像都有。题材与设计领域无关，以免偏袒某套体系；夜空与仪器又给每套体系留足了表现空间。
- **图像**：共享内容只写图像简报（这张图讲什么），每套体系按自己的材质锚点和画风制作图像。共享的中性图片会把每套体系都拉向平庸，所以不提供。
- **组成**：一个落地页、约 10 页 HTML 幻灯片、3 张社交配图。
- **用途**：体系目录里的预览；提取时的迁移测试；修改体系后的回归对比。

## 4. 需求翻译

### 4.1 模糊词有歧义，但不是空的

「高级」常见的意思至少有四种：大面积留白的极简、黑金的奢侈品感、杂志编辑感、精密工业感。agent 做砸往往不是因为听不懂，而是悄悄挑了其中最平庸的一种。翻译要做的，是把这些解读摆到需求方面前。

### 4.2 感觉词词典

- 收录需求方真正会说的词，例如高级、大气、简约、有科技感、温暖、年轻、专业、精致、有氛围感、ins 风、日系、国潮。第一期收 20–30 个。
- 每个词列出几种常见解读。每种解读对应：材质锚点、调性位置、构图比率、推荐的体系（没有对应体系时标为临时方向），以及一张取自范例库的样图。
- 品味笔记会记下每位需求方对每个词偏好哪种解读，下次优先采用。

### 4.3 复述

agent 不用任何术语，把自己的理解说回给需求方，列出几种解读和样图，并提出作品概念。比如：

> 你说的「高级」，我理解为：大量留白、暖灰底、衬线大标题、动效慢而轻。首屏我打算做得像一本技术手册的扉页。

一次最多追问三个问题。需求方挑一种解读，再确认作品概念。

### 4.4 临时方向

如果选中的解读在库里还没有对应体系，就现做一个临时方向。依据是该解读的材质锚点、调性位置和构图比率，加上美学立场和工艺规范，排法借用最接近的种子体系。产出要标明「临时方向」，同样必须通过检查器。同一种解读被选中三次以上时，提议把它升级为正式体系。

## 5. 产出流程

### 5.1 一次产出

1. **需求**：需求方用自己的话说明要做什么，附上素材或参考样例。
2. **简报**：agent 把需求整理成结构化的简报（受众、场合、目的、载体），并在感觉词词典里查出几种解读。
3. **复述**：用大白话说回给需求方，列出解读和样图，提出作品概念。需求方挑选解读，并确认作品概念。
4. **定方向**：有对应体系就用体系，没有就做临时方向。只有需求方拿不定主意，或者这件作品很重要时，才另做对比页。
5. **产出**：按骨架选用叙事单元，按体系选排法，把作品概念落在一两处关键位置。需要生图时，使用需求方的生图方式（见 5.4）。
6. **自查**：先过检查器，再由 agent 按评分标准自查，最后做减法：删掉不影响理解的文字、重复的线和多余的容器。
7. **交付与记录**：需求方提意见；agent 判断这条意见的作用范围，挑选结果记入品味笔记。

简报是给 agent 用的结构化记录；复述是同一份内容讲给需求方听的大白话版本。

### 5.2 意见的作用范围

agent 把每条意见翻译成结构化的修改，并向需求方确认它作用到哪里：只改这一件作品、修改这套体系，还是记为长期偏好。长期偏好要经裁判确认后才生效。

### 5.3 品味笔记

每次挑选都记一条，内容包括：当时的简报、给出了哪些解读和方向、选了哪个、没选哪个，以及理由（换算成具体维度和刻度）。它有三个用途：

1. 提炼偏好规则的提案，经裁判确认后生效。
2. 改进感觉词词典和检索。
3. 指示下一套该做什么体系，依据是临时方向被选中的次数。

### 5.4 生图方式

- 生图方式因人而异。第一次需要生图时，询问需求方用什么服务、什么模型、密钥放在哪里，答案存到仓库之外的个人配置里。之后直接使用；调用失败，或需求方要求更换时，再重新询问。
- 仓库里只放两样东西：生图的接口约定，以及按各体系画风和材质锚点写好的提示词配方。不放任何地址和密钥。
- 各个生图方式的能力不同，比如未必支持透明背景。素材配方要写明需要哪些能力，并给出替代做法。
- 需求方没有生图方式时，改用无图方案或图库，流程照常进行。

## 6. 提取

- **输入**：
  - 网址：读取计算样式，截图，录制动效。CSS 动画和过渡用 `document.getAnimations()` 读取时长、缓动和延迟；JS 驱动的动画逐帧采样元素位置，拟合出时长与曲线；滚动驱动的动画按滚动位置采样。
  - 图片：视觉模型判读加取色聚类。
- **输出**：一份体系草稿，六个部分逐项填写。每个字段都标明来源类型：测得（脚本测量）、判读（视觉模型按评分标准判断）、推断（对设计意图的推测）。意图和材质锚点几乎都属于推断，必须由裁判确认。
- **目标是神似且达标，不是照抄**：
  - 保留参考样例的材质锚点、识别符号、调性位置和画风。
  - 细节按工艺规范重做。
  - 违背美学立场的地方先标出来，说明理由后再修正；需求方可以逐条否决。
- **验证**：两项都通过才能入库。
  - 复现测试：用草稿体系临摹参考样例，逐个维度对比。
  - 迁移测试：用草稿体系渲染标准样张，由裁判判断是否仍一眼看得出是同一套语言，并且依然好看。只做复现测试的话，提取器可能只是学会了照抄这一页。
- **版权**：从品牌网站提取的数值来自公开的 CSS，并不是官方规范。每套体系都记录来源和授权状态，入库只收「受其启发」的版本。

## 7. 系统构成

### 7.1 分工原则

- 知识和数据放在仓库里，流程放在技能里：技能是动词，仓库是名词。
- 技能只依赖索引和格式约定，不依赖目录细节。
- 确定性的工作写成脚本；只有需要审美判断的部分才交给 agent，并且附上评分标准。

### 7.2 仓库与技能

- 体系库和技能放在同一个仓库。
- 技能本体放在 `.agents/skills/`，`.claude/skills/` 下放软链接；本库的技能统一加前缀，和第三方工程技能区分开。
- 目标 agent：Claude Code 和 Codex。

### 7.3 存储格式

每套体系一个目录：

- `SYSTEM.md`：给 agent 读的正文，按六个部分组织，规则都带理由。文件头部写检索字段，包括类别、适用场景、载体、调性位置和材质锚点。
- `tokens.json`：可机读的数值，包括颜色、字号、间距、圆角、动效时长和缓动，采用 DTCG（W3C 设计令牌社区组）格式。
- 排法和范例按载体分子目录存放。

另外提供一个导出脚本，把体系导出为 DESIGN.md，方便在其他工具里使用。DESIGN.md 仍处于 alpha 阶段，所以只把它当作导出格式。

### 7.4 检查器

第一版把所有能机械判断的项写成脚本：

1. **数值合规**：颜色、字号、间距、圆角、时长、缓动都取自体系的 tokens。
2. **对比度**：按 WCAG 计算。
3. **构图比率**：测量跳跃率、版面率和图版率，检查是否落在体系声明的范围内。
4. **中文排版**：避头尾、中西文间距、标点挤压、孤字和寡行。
5. **质感底线**：不出现纯黑或纯白；灰色带色相；阴影的光源方向一致；圆角嵌套正确。
6. **动效**：时长和缓动落在阶梯内；只动 transform 和 opacity；尊重「减少动态效果」设置。
7. **字体**：字体在字体清单内，且授权状态允许当前用途。
8. **防同质化**：相邻叙事单元用了同一种排法时报告；出现等大卡片网格这类模板痕迹时报告。

需要判断的项，比如主角是否唯一、留白是否有意为之、动效编排是否有主次，由 agent 交付前自查，裁判拍板。「模糊截图找视觉焦点」和「动效胶片条评审」放到第 3 阶段。

### 7.5 渲染

第一期三种载体都用 HTML 渲染，由无头浏览器输出网页的截图和录屏、幻灯片的放映与 PDF，以及社交配图的图片。社交配图的文字和版式始终由 HTML 负责，图像模型只生成背景、纹理、插画等素材。

### 7.6 PPTX 导出

决定第一期先交付 HTML 幻灯片，可编辑的 .pptx 放到后面再做（[ADR-0002](adr/0002-html-slides-first-pptx-later.md)）。候选后端是 ppt-master 的 SVG→PPTX 编译层，接入方式是把体系编译成它支持的 SVG 子集，外加一份 `animations.json`。已知情况如下（来自阅读源码，未实际运行）：

- 输出的是原生可编辑的形状和文字，许可证为 MIT。
- 不嵌入字体，目标电脑缺少的字体会被替换，所以只能使用字体清单里标为 PPT 安全的字体。
- 颗粒、内阴影、混合模式、蒙版都要先渲染成图片再放进去；带色阴影可以用原生方式做，但每个对象只能有一层。
- 支持 48 种原生转场（包括平滑切换 Morph）和 203 种对象动画；不支持按段落逐条出现、自定义运动路径和关键帧时间线。
- 只在 PowerPoint 桌面版上验证过。团队同时在用 PowerPoint 和 WPS，所以每次导出前都要向需求方确认目标软件。
- 带有署名保护脚本，如果 fork 后修改，需要先处理这一点。

## 8. 路线

| 阶段 | 内容 | 验收标准 |
| --- | --- | --- |
| 0 打地基 | 存储格式、工艺规范 v0、字体清单 v0、各载体的结构骨架、标准样张内容、检查器 v0；第一个案例；另外两套种子体系；感觉词词典 v0；范例库开始积累 | 每套种子体系都在三个载体上渲染了标准样张，通过检查器，并经裁判认可「耐看」 |
| 1 用起来 | 跑通第 5 节的完整产出流程，覆盖三个载体；编写本库的技能；开始记录品味笔记 | 盲选：用 10 个真实简报，比较「agent 裸跑」与「agent + 本库」，后者至少赢 8 个。赢 6–7 个则继续打磨；赢 5 个及以下，先回头修正方向 |
| 2 提取 | 从网址（含动效）和图片中提取；做复现测试与迁移测试 | 提取出的体系两项测试都通过裁判判断 |
| 3 扩充 | PPTX 导出；临时方向升级为正式体系；词典随品味笔记扩充；增加叙事单元与排法；视觉焦点检测与动效胶片条评审；体系目录页；静态配图导出短视频或动图 | 待定 |

**顺序的理由**：先验证「用得好」，再做提取。如果用了本库的产出在盲选中赢不了裸跑的 agent，后面的提取和扩充就失去了意义。第 0 阶段先做第一个案例，再做另外两套体系：先用一套完整的体系把格式、检查器和品质基准打通，避免三套体系同时返工。

### 8.1 第一个案例：纸本编辑

第一个案例由 agent 全权负责、裁判验收。它定下全库的基调，后两套种子体系照它的标准来做。

- **材质锚点**：暖白哑光纸上的油墨印刷（初稿，制作时再细化）。
- **调性倾向**：静、疏、暖、轻、庄。
- **手感**：像纸一样滑入，带一点摩擦停住，不回弹。
- **交付物**：六个部分齐全的体系，以及标准样张在三种载体上的渲染结果。
- **为什么先做它**：它最直接地体现「材美工巧」，也是最安静、最耐看的一套；纸与墨和中文排版传统一脉相承；和标准样张的题材也贴合：天文台的观测日志，本来就是纸与墨。
- **与 Open Design atelier-zero 的区别**：atelier-zero 同样是暖纸编辑风。本案例靠三点拉开差距：中文排版的工艺；由纸张物理推出的动效手感；作品概念加多种排法。

另外两套种子体系：

| 体系 | 材质锚点 | 调性倾向 | 手感 | 适合 |
| --- | --- | --- | --- | --- |
| 精密工业 | 阳极氧化铝与冷色背光 | 静、密、冷、重、庄 | 快、准、位移短，停得干脆 | 产品发布、方案评审、数据汇报 |
| 孔版印刷 | Riso 孔版印刷的套色、错版与油墨颗粒 | 动、密、暖、轻、谐 | 像盖章一样落下，带一点套色错位的抖动 | 活动推广、社交配图 |

三套体系一套安静、一套冷静、一套热闹，覆盖项目介绍落地页、汇报与分享幻灯片、社交配图三个高频场景。其中孔版印刷用来验证 ADR-0001：热闹的风格也能有质感。
