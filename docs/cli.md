# 命令手册

`pnpm ds` 各子命令的用法、产物和格式约定。运行或修改这些命令前读这份文档；改了命令的行为，同一个提交里改这里。各模块的细节写在对应源文件的文件头。

需要 Node 22.18 及以上和 pnpm 12（`packageManager` 字段会自动切换版本）。

- 安装：`pnpm install`，然后 `pnpm exec playwright install --with-deps --only-shell chromium`（只需 Chromium headless shell）。
- 构建并检查：`pnpm ds build --system <体系目录> --work <作品描述.json> --out <产物目录> [--library <共享资产目录>]`。产物目录里有 `index.html`、`fonts/`、渲染出的 PNG、`report.json` 和 `report.md`。网页作品输出 `web-desktop.png`（宽 1440）、`web-mobile.png`（宽 390）两张整页截图和一段加载并滚动到底的录屏 `web-scroll.webm`；检查器在两个宽度上各跑一遍，只在手机宽度出现的问题会在说明末尾标注。网页版式里按滚动才显示的内容，要放在 `html[data-render="static"]` 下直接显示（截图和检查时页面带这个标记，录屏时没有）。`--library` 默认是当前目录下的 `library/`（放结构骨架 `skeleton/<载体>.json`、字体清单 `fonts/manifest.json`，以及可选的共享内容 `content/<载体>.json`，作品描述用 `{"ref": "键名"}` 引用）。
  - 定制片段文件：作品描述里 `custom` 除了内嵌 HTML 字符串，也可以写成 `{"file": "fragments/hero.html"}`，引用体系目录下 `works/fragments/*.html`（路径相对体系的 `works/`，必须以 `fragments/` 开头、以 `.html` 结尾，不能含 `..`、不能是绝对路径，符号链接解析后也必须还在 `works/fragments/` 内）。`serves` 照常必填。文件不存在、路径不合规或文件为空，按作品描述错误处理（退出状态 2）。规则见 `src/work.ts` 文件头。
  - 录屏入场等待：网页在首屏可见入场全部结束后再停留 800ms，才开始滚动；幻灯片每页在翻页及该页入场结束后停留 600ms，再翻下一页。等待覆盖字体就绪、额外等待、错峰和独立透明度计时，保留动画的真实播放，不快进。每屏／页等待上限为 10000ms（包含字体等待）：为现有 3000ms 初始字体窗口和后续错峰入场、翻页预留 7000ms，同时避免字体停滞、暂停／无限动画或未完成的入场钩子卡住录屏；超时后照常停留并继续。网页只等首屏可见的动画，屏外动效不阻塞；静态截图、PDF 和检查结果不受影响。实现见 `src/render.ts`、`src/web.ts`、`src/slides.ts` 文件头。
  - 入场动效：排法和定制片段里给元素写 `data-ds-enter="fade|rise|fall|left|right"`，可选 `data-ds-order`（组内顺序）、`data-ds-stagger`（写在组容器上）、`data-ds-step`、`data-ds-ease`、`data-ds-distance`，取值名都来自体系的时长阶梯、缓动集、错峰和间距；用法见 `src/choreography.ts` 文件头。检查器会在正常和「减少动态效果」两种条件下记录动画并检查动效规则（`src/checker/rules/motion.ts`）。
    - 初始入场等字体：网页首屏批次和幻灯片初始页（含 URL hash 指定的页）先触发布局以发现使用的字体，再等 `document.fonts.ready`，最多等 3000ms；这给大体积中文字体留出浏览器通常的字体阻塞窗口，同时避免网络停滞让内容一直隐藏。等待时普通入场元素隐藏但保留布局，揭去覆盖层保持盖住内容；字体就绪或超时后按原来的顺序、错峰和时长播放，超时后字体到达不会重播。正常和减少动态效果均适用，`dsSlides.entered()` 包含初始字体等待；滚动后续批次和翻页后的入场不额外等待，静态截图、PDF 和检查器快照绕过等待。
    - 透明度独立计时：体系可在数值文件根部的 `$extensions["io.github.jinhaofang.design-system"].entrance.opacity` 声明 `{"step":"quick","ease":"settle"}`，两个名字分别取自 `ratio.duration` 和 `easing`（例子只在体系有这些名字时可用）；元素用 `data-ds-opacity-step`、`data-ds-opacity-ease` 单独覆盖。rise/fall/left/right、draw-*、stamp、peel-* 的 transform 与 opacity 分为两条动画，共用「名次 × 错峰 + 额外等待」，各自按时长和缓动运行；draw 同时淡入，peel 同时淡出。元素未覆盖的字段先取体系默认，没有体系默认则沿用该元素的位移计时；体系和元素都未声明时行为不变，fade 与减少动态效果也沿用现有行为。未知名字在构建前校验失败（退出状态 2）；`motion.json` 分别记录两条动画，`dsSlides.entered()` 等两条都结束。幻灯片翻页目标的揭去覆盖层（含子树）保持可见、盖住内容，回访前恢复盖住状态，停稳后才揭去；截图和 PDF 仍使用已揭去的终态。
    - 额外等待：元素可写 `data-ds-wait="slow"`，取值为体系 `--ds-duration-*` 的名字（这里的 `slow` 仅在体系有此档时可用）；不写时额外等待为 0。实际延迟为「组内名次 × 错峰 + 额外等待」，只影响声明它的元素，同组其他元素照常开始；如标题用 `data-ds-step="slow"`，下划线可用 `data-ds-enter="draw-x" data-ds-order="1" data-ds-wait="slow"` 等标题完成后再划出。网页加载和滚动触发、幻灯片首屏及翻页停稳后的入场都适用，`dsSlides.entered()` 等待包含额外等待在内的所有入场结束；减少动态效果时去掉额外等待和错峰。未知名字在渲染前校验失败（退出状态 2），错误列出名字、序列项和对应元素的起始标签；`motion.json` 的 `delayMs` 记录合计延迟。
    - 另有三种动作：`data-ds-enter="draw-x"` 从左到右划出（左端起笔，scaleX 从 0 到自然尺寸），`draw-y` 从上到下划出（顶端起笔，scaleY）；`stamp` 按下落定（放大后缩回自然尺寸，同时淡入）；`peel-left|peel-right|peel-up|peel-down` 揭去覆盖层（沿所写方向移出自身尺寸的 100%，结束后保持离开）。它们同样支持顺序、错峰、时长和缓动属性，网页按滚动触发，幻灯片按进页触发。`stamp` 要求体系数值文件声明 `"motion":{"stampScale":{"$type":"number","$value":<大于1的有限数字>}}`，生成 `--ds-motion-stampScale`，不乘载体基准值；缺少、类型错误或值不合规会在渲染前报错（退出状态 2）。减少动态效果时划出直接呈现完成状态，按下落定只淡入，揭去只淡出，淡入淡出取最短时长并去掉错峰。静态渲染（`data-render="static"`，包括社交配图）同步把覆盖层设成终态；正常播放以 `fill:both` 保留揭去的终态，完成后隐藏覆盖层及子树，检查器不把它们计入对比度或构图。打印样式也让所有覆盖层及其子树处于已揭去状态（包括未访问的幻灯片和正在翻页的目标页），供 PDF 使用；普通入场内容照常显示，翻页的位移、投影和暗影照常清除。动作元素应支持 transform（文字用块或 inline-block 元素）；覆盖层的定位和裁切由排法或定制片段声明。网页和幻灯片的动画记录统一只存入 `motion.json`（`{animations,reduced}`），`report.json` 只存检查结论、不重复记录；`buildAndCheck()` 返回路径 `artifacts.motionJson`。记录包含两种偏好下的动画（`entrance`、`durationMs`、`delayMs`、`easings`、`properties`、`keyframes` 及位置），可用于核对时长、缓动、属性和缩放倍数。
  - 幻灯片翻页：体系目录可放 `slides.transition.json`，五个必填字段均引用该体系生成的 CSS 变量，例如 `{"duration":"--ds-duration-slow","easing":"--ds-easing-settle","shadow":"--ds-shadow-page","shadeColor":"--ds-color-page-shade","retreat":"--ds-space-4"}`。`duration` 引用时长阶梯，`easing` 引用缓动集，`shadow` 引用左缘投影，`shadeColor` 引用带透明度的暗影色（alpha 控制深浅），`retreat` 引用间距阶梯（后退像素距离）；不存在或类型不符的引用、缺字段、未知字段按校验失败处理（退出状态 2）。未声明时瞬间切换；向前从右侧进入一页宽度，向后镜像。减少动态效果时直接切换。页内 `onEnter` 钩子和 `ds:slide-enter` 在翻页停稳后触发，`dsSlides.entered()` 等翻页和页内入场全部完成；连按时取消上一轮过渡与旧页入场、清理位移和暗影，再翻到最新目标，等待会跟随最新一轮。截图、PDF 用终态，录屏保留真实过渡；幻灯片产物新增 `motion.json`，分别保存正常和减少动态效果的动画记录。模块约定见 `src/slides-transition.ts`、`src/slides-runtime.ts` 文件头。
  - 退出状态：0 表示没有错误（只有警告也是 0）；1 表示报告里有错误；2 表示体系或作品描述校验失败、没有报告，原因打印在 stderr。
  - 试跑夹具：`pnpm ds build --system test/fixtures/systems/mini --work test/fixtures/works/clean.json --out out/clean --library test/fixtures/library`。
- 校验体系：`pnpm ds validate-system --system <体系目录> [--library <共享资产目录>]`，只跑体系校验（SYSTEM.md、数值文件、字体引用、体系专属单元），一次列出全部问题；退出状态 0 通过，2 失败。体系格式见 `src/system.ts`、`src/tokens.ts` 文件头；体系专属叙事单元放在体系目录的 `skeleton/<载体>.json`。
- 标准样张内容：`library/content/`（设定见 `SETTING.md`，共享内容 `web.json`、`slides.json`、`social.json`，键名为 `<单元>.<槽位>` 或 `<单元>.<实例>.<槽位>`，图像槽位只写图像标识，图像简报清单在 `images.json`；图片由各体系自己提供，放在体系目录的 `images/<标识>.<svg|webp|png|jpg>`，构建时按作品用到的标识查找并复制进产物的 `images/`，缺了就报错并列出全部缺少的标识）。
- 类型检查：`pnpm typecheck`。
- 完整验证：`pnpm verify`，由 `scripts/verify.ts` 按 `STEPS` 的顺序逐步运行，每步先打印 `[verify]` 标签；前一步失败就停止，并保留该命令的退出码，全部通过时以 0 退出。新增检查只在 `STEPS` 中加一项，例如 `{ label: '检查名称', command: ['pnpm', '对应脚本名'] }`，放在类型检查之后、测试之前；同时在 `package.json` 登记对应的独立脚本。
- 注释位置检查：`pnpm check:comments [仓库根目录]`（默认当前目录），只扫描进 git 的 `.ts`、`.mts`、`.cts`、`.js`、`.mjs`、`.cjs` 工作区文件，包括体系图像生成脚本和进 git 的执行技能脚本；未跟踪文件、`.liquid`、`.css` 不查。可选 shebang 后只允许第一段块注释或连续行注释，空行隔开的第二段和其他位置的任何注释（包括指令注释）都报出 `文件:行 说明`；字符串、模板文本和正则里的类似文字不算注释。退出状态 0 通过、1 违规、2 用法或运行环境错误，`--help` 打印用法。语法树扫描用固定的 `typescript-parser` 别名（TypeScript 6.0.2 compiler API），类型检查仍用 TypeScript 7。
- 文档命令检查：`pnpm check:doc-commands [仓库根目录]`（默认当前目录）；`--help` 查看用法。只扫描进 git 的根部规则文档（`AGENTS.md`、`CLAUDE.md`、`README.md`、`GLOSSARY.md`）、`docs/` 下除 `reports/` 和 `adr/` 以外的 Markdown，以及 `.agents/skills/`、`.claude/skills/` 下进 git 的 Markdown，只看反引号里的内容（含代码块）。`pnpm` 命令须是项目脚本或 `scripts/pnpm-builtins.ts` 的内置命令快照；快照版本须与 `packageManager` 一致，升级时按该文件头的方法更新。`pnpm ds` 的子命令须在 `src/cli-commands.json` 中，CLI 与检查器共用此表；不检查子命令的参数和选项。`node` 后的相对文件路径必须进 git，并且在工作区里实际存在、可读（软链接要能解析到文件）；忽略的第三方路径、选项、占位符、动态路径和绝对路径跳过。命令只当文本分析，不执行；输出扫描文件数、命令数（含跳过项）和跳过数，违规逐条指出 `文件:行 命令 原因`。退出状态 0 通过、1 违规、2 用法或运行环境错误。
- 提交信息检查：`pnpm install` 的 `prepare` 自动把 Git 的仓库配置 `core.hooksPath` 设为相对路径 `.githooks`（多个 worktree 共享该配置，各自使用自己的钩子文件）；可用 `node scripts/install-hooks.ts` 重新启用。提交时 `.githooks/commit-msg` 调用 `node scripts/commit-msg.ts <提交信息文件>`，按 `AGENTS.md` 检查类型、非空范围（内容不限）、中文摘要、正文和最后一段的 `Refs`/`Role`，禁止署名行，一次列出全部违规。合并进行中（存在 `MERGE_HEAD`）跳过；忽略编辑器中以 `#` 开头的行及剪刀线以下内容；detached HEAD 的分支名视为空。
  - 本机复现 CI：`pnpm check:commits origin/main ticket/36`，通用形式为 `pnpm check:commits <起点> <来源分支名>`。只检查 `起点..HEAD` 的非合并提交，使用最终信息，保留 `#` 行和剪刀线；按完整提交号报告违规。起点之前的旧提交不检查。CI 拉取完整历史，PR 用来源分支名，推送用当前分支名，在独立步骤中运行；本项不加入 `pnpm verify`。
  - 退出状态：0 通过，1 提交信息违规，2 用法或运行环境错误；各入口支持 `--help`。入口测试在 `test/commit-checks.test.ts`，用提交信息文件和临时 Git 仓库驱动钩子及分支检查命令。
- 检查命令辅助：`scripts/cli.ts` 的 `runCheckCommand(usage, check)` 接收用法和参数处理函数，后者返回全部违规消息；入口把返回值赋给 `process.exitCode`。`--help` 打印中文用法并以 0 退出；参数错误用 `usageError('中文原因')` 抛出（也可用 Node 的 `parseArgs`，其参数错误会统一转为中文），打印原因和用法、以 2 退出；违规逐条打印到 stderr、以 1 退出；运行环境错误打印中文原因、以 2 退出。现有 `ds` 命令的约定保持不变。
- 范例库：每条范例一个目录 `library/exemplars/<id>/`，里面是 `exemplar.json` 和媒体文件（截图或录屏）。目录名必须等于 `id`。
  - 字段：`id`、`title`、`sourceType`（`external` 外部收集 / `copy` 临摹 / `original` 原创）、`sourceUrl`（外部收集和临摹必填）、`copyright`（版权方）、`carrier`（`web` / `slides` / `social`）、`systems`（支撑哪些种子体系，如 `paper-editorial`、`precision-industrial`、`riso-print`）、`media`（`kind`：`screenshot` / `recording`；`status`：`present` 时 `file` 必须存在，`pending` 表示待补，已批准的范例不能是待补）、`annotation`（`highlights` 出色之处、`reasons` 原因、`scenes` 适合的场景、`materialAnchor` 材质锚点、`tonality` 调性位置）、`approval`（`status`：`candidate` / `approved` / `rejected`；已批准和已拒绝必须带 `date`，格式 `YYYY-MM-DD`，候选不带）。
  - `tonality` 五个键 `静动`、`疏密`、`冷暖`、`轻重`、`庄谐`，值 1–5，1 靠近键名第一个字（静、疏、冷、轻、庄），5 靠近第二个字。
  - 校验：`pnpm ds validate-exemplars [--library <目录>]`。退出状态 0 表示全部完整，1 表示有问题（逐条打印在 stderr，写明范例标识和字段）。
  - 按来源类型列出：`pnpm ds list-exemplars [--source external|copy|original] [--paths] [--library <目录>]`。默认每行一条（标识、来源类型、批准状态、载体、来源链接、媒体文件，制表符分隔）；`--paths` 只打印存在的媒体文件路径。仓库公开之前移除外部截图：`pnpm ds list-exemplars --source external --paths | xargs rm`，再把相应范例的 `media.status` 改成 `pending`。
  - agent 只提交候选（`approval.status` 为 `candidate`），批准和拒绝由裁判决定。
- 感觉词词典：每个词一个文件 `library/lexicon/<id>.json`，文件名（拼音）必须等于 `id`。格式见 `src/lexicon.ts` 文件头。
  - 字段：`id`、`word`（感觉词本身）、`phrasings`（需求方常见说法，至少一条）、`interpretations`（解读，至少两种；同一个词内 `name` 和 `materialAnchor` 不能重复）。
  - 每种解读：`name`、`description`（大白话，要落到色彩、字体、版面、动效等具体决定上）、`materialAnchor`、`tonality`（五个键同范例，值 1–5）、`composition`（构图比率倾向，`跳跃率`、`版面率`、`图版率` 三个键，值 `低` / `中` / `高`）、`recommendation`、`samples`、`approval`。
  - `recommendation`：`{"system": "paper-editorial" | "precision-industrial" | "riso-print"}`，或临时方向 `{"system": "临时方向", "borrowLayoutsFrom": <种子体系>, "direction": <一句话方向>}`。
  - `samples`：`{"status": "pending"}`（待补）或 `{"status": "present", "exemplars": [范例标识...]}`，标识必须在 `library/exemplars/` 中存在。样图可以在任何确认状态下待补。
  - `approval`：按解读逐条确认，格式同范例（候选不带 `date`，已批准和已拒绝必须带 `YYYY-MM-DD`）。词典由 agent 负责确认（需求方 2026-10-11 授权：需求方不是设计领域的）：新解读先以候选提交，agent 按美学立场和工艺规范审过后改为批准或拒绝；与工艺规范冲突的（纯黑纯白、写实贴图、等大卡片、应用界面）改写或拒绝。
  - 校验：`pnpm ds validate-lexicon [--library <目录>]`，退出状态 0 表示全部完整，1 表示有问题（逐条打印在 stderr，写明词条标识和字段）。
  - 列出：`pnpm ds list-lexicon [--status candidate|approved|rejected] [--system <种子体系>|临时方向] [--library <目录>]`，每种解读一行（词条标识、词、解读名、推荐体系、确认状态、样图标识或「待补」，制表符分隔）；状态或体系写错时退出状态 2。
- 测试：`pnpm test`。测试文件并发数取可用 CPU 核数（含 `taskset` 的限制）和 4 的较小值；普通单测和钩子时限为 60 秒，多载体回归成功用例为 120 秒。`pnpm test --reporter=verbose` 可查看逐用例耗时。CI 工作流可手动触发，输出实际资源和逐用例耗时，失败时保存检查报告、动效记录为 `test-reports` 产物；不自动重试。测试只通过 `buildAndCheck()`（`src/build-and-check.ts`，命令行入口 `src/cli.ts` 是它的薄封装）以及它之上的 `buildOverview()`（`src/overview.ts`）、`regress()`（`src/regress.ts`）驱动夹具体系和夹具作品，断言报告和产物规格，不测内部函数，不做像素比对。范例库的测试在 `test/exemplars.test.ts`，通过 `validateExemplars()` 和 `listExemplars()` 两个入口及 CLI 命令驱动临时目录里的范例。开发护栏的测试通过最小命令驱动夹具，只断言退出码和输出；共享命令行辅助的测试在 `test/cli-helper.test.ts`，注释位置检查的测试在 `test/check-comments.test.ts`，对临时 git 仓库运行检查命令。
- 排法总览：`pnpm ds overview --system <体系目录> --out <产物目录> [--library <共享资产目录>] [--carrier <载体>...] [--canvas <画幅>...]`。为任意体系生成作品：网页、幻灯片各一件（按骨架顺序，每个单元的每种排法依次出现一次），社交配图每个画幅、每种排法一张；内容取共享内容里该单元的第一个实例，只用 `{"ref": 键名}` 引用，不依赖具体键名。每件作品走一遍「构建并检查」，产物在 `<载体>/` 和 `social/<画幅>/<单元>-<排法>/` 下，`overview.md` 汇总各构建的错误和警告数；体系没有排法或共享内容没覆盖的单元列为「未覆盖」，不算错误。退出状态同 `build`（有构建失败也是 1）。
- 体系总览页：`pnpm ds system-page --system <体系目录> --out <产物目录> [--library <共享资产目录>] [--overview-dir <排法总览目录>] [--works-dir <标准样张目录>]`。为任意体系生成一页交互页面（不要和 `overview` 排法总览混淆）：意图与关键规则（规则、理由、适用边界三列）、标准样张、排法、材质锚点、色彩（按名称前缀归组成色带，SYSTEM.md 的色彩表是图例）、字体（按字体家族分块：样句、已加载字重并排、一行授权、角色对应）、字阶（一档一行，大字号样本截断）、间距与圆角阶梯、版面、质感与识别符号，动效部分每种入场方式、每档时长、每条缓动、错峰都有重放按钮（时长、缓动格子带 SYSTEM.md 表里的「用在」），页面上有「减少动态效果」开关；页面用体系自己的数值、字体和质感排版。SYSTEM.md 里的表格渲染成表格；排法表（表头含「排法」「说明」，行如 `` `id` 中文名 ``）给每种排法配中文名和说明，不再在版面里重复。链接与缩略图：`--overview-dir` 是排法总览的产物目录，社交配图的每种排法显示对应构建的缩略图（优先小红书画幅，没有则取第一个画幅）并链到该构建，网页、幻灯片链到整体总览；`--works-dir` 是标准样张产物目录（一件作品一个子目录），样张显示缩略图并链到各自产物，网页长截图按 5:4 固定比例从顶部裁切，其他载体保持原图比例；样张说明栏沿用现有卡片的 14rem 最小宽度（以可用宽度为上限），不随缩略图挤窄；链接按相对路径写进页面，没给就在页面上写明还没有生成；库里该体系已批准的范例会列出并复制媒体文件，网页范例带来源链接。体系可在 `<体系目录>/system-page/header.html` 提供自己的页头片段（Liquid 模板，变量 `system.{id,name,category,materialAnchor,scenarios,carriers}`，可带一段 `<style>`，只作用于页头），没有时用默认页头。产物目录里有 `index.html`、`fonts/`、`web-desktop.png`、`web-mobile.png`、`exemplars/`、`replays.json`（两种动态效果设置下的动画记录）、`report.json` 和 `report.md`；检查跳过构图比率和防同质化，其余规则照常，退出状态同 `build`。入口 `buildSystemPage()`（`src/system-page.ts`）。
- 预览：`pnpm ds preview --dir <产物目录> [--port <端口>] [--host <地址>]`，默认 `http://127.0.0.1:4173/`，在本地起静态服务直到 Ctrl+C。目录可以是单件作品、排法总览、体系总览页或回归产物；根路径 `/` 是导航入口：目录是回归产物（`<体系>/system/`、`works/<名>/`、`overview/`）、单个体系目录（含 `system/` 或 `overview/overview.md`）时按体系分组，体系总览页放最前作主入口，标准样张显示缩略图和错误/警告数，排法总览合成一个条目（带总错误/警告数），点开是生成的 `/_overview/<排法总览目录>/` 列表页（按载体、画幅分组的缩略图，各自链到构建，报告在这一页），首页不再平铺这些构建；目录是单个排法总览（根下有 `overview.md`）时首页直接就是这张列表；其他形态（单件作品、任意文件夹）仍平铺列出目录下所有产物（含 `index.html` 的子目录）及其错误/警告数、截图、录屏和报告；网页能滚动、幻灯片用方向键翻页、字体照常加载，录屏支持拖动。端口被占用或目录不存在时退出状态 2。入口 `startPreview()`（`src/preview.ts`，分组页在 `src/preview-nav.ts`）。
- 回归：`pnpm ds regress [--systems <目录>] [--out <目录>] [--library <目录>]`（默认 `systems`、`out/regress`）。种子体系放在顶层 `systems/<体系标识>/`（`SYSTEM.md`、`system.tokens.json`、`layouts/` 等，格式同体系目录），该体系的标准样张作品描述放在 `systems/<体系标识>/works/*.json`（一份文件一件作品，社交配图每个画幅一份）。对每套体系先跑全部标准样张，再跑它的排法总览，最后生成体系总览页（链到前两者），产物在 `<out>/<体系标识>/works/<文件名>/`、`<out>/<体系标识>/overview/` 和 `<out>/<体系标识>/system/`；任何错误、构建失败、缺少标准样张都以退出状态 1 结束，体系目录不存在为 2。CI 里有手动触发的 `regress` 工作流（`.github/workflows/regress.yml`），缓存 `.cache/fonts`。
- 抓取字体：`pnpm ds fetch-fonts [--library <目录>] [--font-cache <目录>]`，按字体清单把字体下载到 git 忽略的 `.cache/fonts`并核对 sha256，走环境变量 HTTPS_PROXY；构建只读这个缓存。检查器用字体文件内部的 PostScript 名匹配清单，并用 cmap 检查缺字。
  - 构建字体子集：网页、幻灯片、社交配图、排法总览和体系总览页在渲染前按最终页面用字生成中文字体子集。用字取解码后的 DOM（含定制片段和未显示的内容）及 Chromium 的实际排版文字（含 CSS 计数器、伪元素和大小写转换），网页覆盖 1440/390 两种宽度，幻灯片逐页收集，两种动态效果偏好均覆盖。只处理清单标为 `cjk`、采用 OFL-1.1 且核对过完整许可、没有实际保留字体名称声明的字体；已核对的固定官方 URL 与原文在 `src/font-subset-licenses.json`，清单的本地 `license.file` 也可提供完整 OFL（版权头声明保留名称时不处理）。未知许可、没有可核对原文、有保留名称的字体及纯西文字体保持原样，不自动改名。子集保留原文件名、格式、字体名称、字形风格、版权和授权元数据及排版特性，完整许可随子集放在 `fonts/<字体标识>.OFL.txt`，产物仍可直接从磁盘打开；缓存只读，检查器读产物字体的 cmap，PostScript 名匹配和斜体判定照常。子集化失败按构建失败处理（退出状态 2），不静默交付完整字体。
  - 斜体：清单条目可选 `style`（`normal` 或 `italic`，不写按 `normal`）。斜体字面单独建一条，有自己的文件和 PostScript 名，按 PostScript 名匹配；构建生成的 `@font-face` 带 `font-style`。体系要用斜体，就在数值文件里再加一个 `font.<角色>`（如 `font.body-italic`）并用 `fontId` 引用斜体条目，这样它的 `@font-face` 才会进产物。检查器规则 `fonts/style-mismatch`：斜体文字用到的字体里没有斜体字面（浏览器会硬倾斜正体），或正体文字用上了斜体字面，都是错误。
- 重新生成夹具字体：`pnpm fixture-font`（输出到 `test/fixtures/font-cache/`；缺字夹具用的 `龘` 和 U+E000 被故意排除在子集之外）。夹具文字里新增汉字后要重跑并提交结果。
